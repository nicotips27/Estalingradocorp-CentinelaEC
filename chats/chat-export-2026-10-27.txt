3. FIX UPSTREAM: PRISMA SCHEMA BANNED FIELDS
--------------------------------------------------------------------------------
Problema: plugin `admin` de Better Auth envía campo `banned` en creación de usuarios,
pero esquema Prisma no lo declaraba → "Unknown argument `banned`" → 422 FAILED_TO_CREATE_USER.

Fix aplicado:
- prisma/schema.prisma: + banned Boolean @default(false), banReason String?, banExpires DateTime?
- prisma/migrations/20261027010000_add_user_ban_fields/migration.sql: 3 ALTER TABLE
- Rebuild de imagen Docker (4 min) → migración aplicada en entrypoint → sign-up/sign-in OK

5. AUTO-LOGIN FUNCIONANDO
--------------------------------------------------------------------------------
Flujo implementado en main.js:
1. Usuario pulsa Ctrl+0 → carga globe.html (loader) en WebContentsView con preload
2. main.js: health check → si down: docker desktop start + compose up -d (stream log)
3. Poll /api/health hasta 200
4. GET /api/auth/setup-status → si needsSetup: POST /api/ba/sign-up/email (crea usuario)
5. POST /api/ba/sign-in/email → parsea Set-Cookie → session.defaultSession.cookies.set
6. loadURL(http://localhost:3000/) → globo abre sin login manual

Credenciales guardadas en %APPDATA%\centinela-beta\centinela-globe.json (email+password)
